# IndieMatch — ナノインフルエンサー分析

個人開発者・小規模ブランドが、フォロワー 1,000〜20,000 人規模のインフルエンサーを探し、費用対効果を見積もるためのサービス。
裏側では、データ収集からモデルの再学習・昇格判定・監視までを自動化したパイプラインが 1 日 4 回動いている
（YouTube 718 チャンネル / Instagram 647 アカウントを収集済み）。

**サービス**: https://indie-matching-v2-azure.vercel.app
（このリポジトリは紹介用。コードは非公開）

## 構成
![architecture](docs/architecture.png)

| | |
|---|---|
| 収集 | YouTube Data API v3 / Instagram Graph API（Business Discovery） |
| 学習 | scikit-learn（線形回帰・Ridge）、交差検証はアカウント単位の GroupKFold |
| 実行 | GitHub Actions（1 日 4 回）。収集データと状態はリポジトリにコミットして持ち回る |
| 昇格 | 候補モデルが現行より R² で相対 5% 以上悪ければ却下（113 回の判定で却下 15 回） |
| 配信 | Firestore → Next.js（Vercel）、Firebase Auth |
| 監視 | 実行ログ・しきい値アラート（Slack）・モデル監視画面 |

## 一番力を入れたこと: そのモデルに意味があるかを測る
同じ分割・同じ指標で、機械学習を使わない手法と比べた。

| 予測 | 機械学習なしの基準（過去の中央値など） | 現行モデル | 差 |
|---|---:|---:|---:|
| Instagram いいね | R² 0.779 | 0.801 | +0.022 |
| Instagram コメント | R² 0.251 | 0.433 | **+0.182** |
| YouTube 再生数 | R² 0.432 / MAE 21,085 | 0.477 / 22,074 | R² は上がるが MAE は悪化 |

- いいね数はほぼ過去の実績で決まり、モデルの上積みは小さい → **モデルを外す候補**にした。
- コメント数は投稿の中身に左右され、機械学習が効いている → 残す。
- 勾配ブースティングとも比べたが、3 つとも線形回帰が上回った（目的変数を log 変換すると関係がほぼ線形、データが少なく木が過学習）。

## 設計で気をつけたこと
- **GroupKFold**: 1 アカウントに約 15 投稿あるため、普通の KFold だと同じアカウントが学習と検証の両方に入り、精度が高く出すぎる。
- **評価はナノ層だけ**: 全データの R² は「100 万人と 1,000 人を区別できるか」を測っているだけ。利用者が知りたい範囲（1,000〜20,000 人）で測る。
- **個人情報の二層化**: 識別子は内部だけ。公開用はフォロワー数の幅・都道府県・ジャンルに粗くし、組み合わせから個人を特定されないようにした。
- **検証できないものは検証済みに見せない**: Instagram のリーチは API で取れないため、仮定値であることを画面に明示している。
- **収集の効率化**: 候補探しを検索 API から「動画 URL → チャンネル」の解決に変え、1 アカウントあたりの API 消費を約 190 分の 1 にした。
